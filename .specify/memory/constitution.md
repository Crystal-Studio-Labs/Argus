# ARGUS Project Constitution

## Core Principles

### I. Precision & Objectivity
All code reviews and evaluations must focus strictly on actual changes in the pull request diff. Generic recommendations or subjective preferences are prohibited. Every finding must be actionable and precise.

### II. Architecture First
Adherence to system architecture defined in `architecture.md` supersedes style or formatting preferences. Changes must comply with Node.js GitHub Action standards and Gemini/NVIDIA API contracts.

### III. Zero Unfinished Code (ARGUS-01)
No function body or pull request change may introduce unresolved placeholder comments (`// TODO`, `// FIXME`) or empty placeholder routines without raising an explicit warning or block severity finding.

### IV. Visual Structural Clarity (ARGUS-03)
Every pull request introducing structural or file topology changes must include an interactive visual representation (Mermaid.js flowchart) generated by the Atlas visualizer stage.

### V. Automated Verification & Test Supremacy
Every feature, skill, or core action modification must be accompanied by unit tests run natively via `npm test` (`node --test`) and verified clean via `npm run lint`.

## Technology Stack & Constraints

- **Runtime**: Node.js 20+ GitHub Action
- **AI Models**: Google Gemini API (`@google/genai`) / NVIDIA OpenAI-compatible API (`openai`)
- **Workflow SDKs**: `@actions/core`, `@actions/github`
- **Evaluation Pipeline**: Sequential 3-stage execution (`Atlas` -> `Athena` -> `Hermes`)
